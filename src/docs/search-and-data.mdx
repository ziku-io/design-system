# Search and data

Two patterns every app repeats. Both have one implementation here — don't hand-roll either.

## Search: `CommandMenu`

[cmdk](https://cmdk.paco.me) palette. It binds ⌘K / Ctrl+K itself, so mounting it once anywhere is enough.

<Canvas of={Search.Default} />

```tsx
<SearchTrigger onClick={() => setOpen(true)} />
<CommandMenu
  open={open}
  onOpenChange={setOpen}
  groups={[
    { heading: "Go to", items: [{ id: "/projects", label: "Projects", icon: FolderIcon, onSelect: () => router.push("/projects") }] },
    { heading: "Actions", items: [{ id: "new", label: "New project", icon: PlusIcon, shortcut: "⌘N", onSelect: createProject }] },
  ]}
/>
```

- `SearchTrigger` is the header control: it looks like an input, behaves like a button. In `AppShell` it goes in `headerActions`.
- Leave `open` off entirely and the menu manages itself — the trigger is then optional.
- `keywords` adds hidden match terms. `shortcut` is display only; bind the actual key yourself.
- For server-side results, pass `onQueryChange` and feed the response back through `groups`.
- Selecting an item closes the menu. `onSelect` runs first.

Rules: one palette per app, groups ordered navigation first then actions, and every item gets an icon.

## Data: `DataTable`

[TanStack Table v9](https://tanstack.com/table) under a declarative column model, with the toolbar ported from the nieusync internal table: filter chips, a multi-column sort stack, grouping, column visibility and saved views.

<Canvas of={Data.Default} />

```tsx
const columns: DataTableColumn<Deal>[] = [
  { key: "name", header: "Deal", icon: UserIcon },
  { key: "stage", header: "Stage", icon: CircleDashedIcon, facet: true, order: ["Lead", "Won", "Lost"],
    render: (r) => <Badge>{r.stage}</Badge> },
  { key: "value", header: "Value", value: (r) => r.value, render: (r) => euros(r.value),
    className: "text-right tabular-nums" },
]

<DataTable
  columns={columns}
  data={deals}
  rowId={(d) => String(d.id)}
  viewKey="deals"
  presets={[{ id: "open", name: "Open", icon: "funnel",
              state: { columnFilters: [{ id: "stage", value: ["Lead"] }] } }]}
/>
```

### Columns

One object per column, not a TanStack `ColumnDef`:

- `key` / `header` — id and visible name. A column with no `header` is furniture (row menus, checkboxes): never offered in a picker, never hidden by the user.
- `value` — what to sort, filter and search on. Return the **visible label**; filters and groups display it verbatim. Defaults to `row[key]`.
- `render` — the cell. Independent of `value`, so a badge can sort by its text.
- `facet: true` — turns on the distinct-values filter, and allows grouping by this column.
- `order` — fixed order for groups and filter options (`["Lead", "Won", "Lost"]`), instead of alphabetical. Labels not in the list sort last.
- `icon`, `className`, `sortable: false`.

### Filtering

Chips on the bar under the toolbar. A facet column gives checkboxes with counts; any other column gives a "contains" text box. A chip with nothing in it stays visible and editable rather than being silently dropped.

<Canvas of={Data.Filtered} />

### Ordering

Headers sort on click. The sort icon opens the full stack — several columns applied in order, each with its own direction — because one column is rarely the whole answer.

### Grouping

Group by any facet column: collapsible group rows with counts, ordered by the column's `order`.

<Canvas of={Data.Grouped} />

### Views

The tabs across the top. "All" plus whatever the page pins through `presets`, plus whatever the user saves with `+`. The active view holds the filters, sorts, hidden columns, grouping and layout, and **every change is persisted as it happens** — no save button.

- `viewKey` is the localStorage key. Without it nothing is saved.
- `presets` are the page's own views; they can be renamed and reset but never deleted.
- The `…` menu renames the view, changes its icon, drills into each setting, and exports the table when `csv` is set.
- A view saved before a column existed is pruned on load, so renaming a column does not strand a filter that matches nothing.
- A new view starts as a copy of the view on screen, filters and all, not as a copy of the defaults.

#### Views on a server

localStorage means a view cannot be shared, does not follow a person to a second
machine, and goes with a cleared profile. Pass `viewsBackend` and it lives
wherever the app puts it.

<Canvas of={Data.ServerViews} />

```tsx
<DataTable
  columns={columns}
  data={deals}
  viewKey="deals"
  viewsBackend={{
    list: () => api.get<SavedView[]>("/views?tableKey=deals"),
    create: (view) => api.post<SavedView>("/views", { ...view, tableKey: "deals" }),
    update: (id, patch) => api.patch(`/views/${id}`, patch),
    remove: (id) => api.delete(`/views/${id}`),
  }}
/>
```

- The save form gains "Share with everyone". Unchecked by default: a view is one
  person's until they say otherwise.
- The browser's views and the server's live side by side. Only the server's are
  pushed back, and their state on a debounce, because every character typed into
  the search box is a change to the active view.
- Views saved before the backend existed migrate up on first load, privately,
  and are skipped if the server already has one by that name (the same person on
  a second machine).
- `canDelete: false` on a view hides its delete. The **server** enforces who may
  delete what; this only keeps the UI from offering what would be refused.
- If `list` rejects, the table draws with the browser's own views. A table that
  will not render is worse than a table missing a view.

#### Export

`csv={{ filename: "deals", decimal: "," }}` puts "Export CSV" in the `…` menu.
What comes out is what is on screen: the filters and sort in force, the visible
columns in their visible order, and the flat row set even when grouping or the
board is on.

`decimal` is one choice, not two. Excel splits a CSV on the list separator its
locale names, so a comma decimal ships with semicolon delimiters; setting them
separately is how a file opens as garbage in the locale it was written for. The
file carries a UTF-8 BOM, without which Excel on Windows mangles every accent,
and a field starting `=`, `+`, `-` or `@` is prefixed with an apostrophe so a
spreadsheet does not run somebody's text as a formula.

### Board

Pass `renderCard` and give the grouped column an `onSet`, and the layout toggle appears. Cards drag between columns; `onSet` is called with the label of the column they land on.

<Canvas of={Data.Board} />

```tsx
<DataTable
  columns={columns.map((c) =>
    c.key === "stage" ? { ...c, onSet: (row, stage) => save(row, stage) } : c,
  )}
  data={deals}
  rowId={(d) => String(d.id)}
  defaultMode="board"
  defaultGroup="stage"
  boardSubtitle={(rows) => euros(rows.reduce((n, r) => n + r.value, 0))}
  renderCard={(d) => <DealCard deal={d} />}
/>
```

Drag and drop is native HTML5, which never fires on touch, so every movable card
also carries a "move to" menu listing the other columns. One tap, or Tab and
Enter, does what the drop does. That is what makes the board usable on a tablet
and reachable from a keyboard; a DnD library is still the upgrade path, and what
would justify it is reordering inside a column, which a menu cannot express.

### Pagination

`pageSize` adds a pager. Grouping and the board always show the whole set, so the pager steps aside while either is on. Everything is filtered and sorted in the browser; a server-driven list is not wired up yet — `onStateChange` gives you the active view's state if you want to mirror it into the URL.

For a table that is not a list of records — a summary, a spec sheet — use the raw `Table` components instead.
