All three sit inside `AuthLayout` (centered card, optional logo and footer).

## Login

<Canvas of={Auth.Login} />

```tsx
<AuthLayout
  logo={<Logo />}
  footer={
    <>
      By continuing you agree to our <a href="/terms">Terms</a>.
    </>
  }
>
  <LoginForm
    onSubmit={async ({ email, password }) => {
      await signIn(email, password);
    }}
    error={serverError}
    providers={
      <Button variant="outline">
        <GoogleLogoIcon /> Google
      </Button>
    }
  />
</AuthLayout>
```

Behaviour that is fixed across apps:

- Client validation with zod (`loginSchema`, exported). Errors show under the field.
- Submit button disables and shows a spinner while `onSubmit` is pending.
- Server errors go in the `error` prop and render in a destructive alert above the fields.
- `autoComplete` attributes are set so password managers work.

## Forgot password

Pass `sent` once the request succeeds; the block swaps to the "check your inbox" state. Message is deliberately the same whether or not the account exists.

## What the app still owns

Session handling, redirects after success, OAuth callbacks, rate limiting. The blocks are UI only.
