# Design tokens

Colours are CSS variables in `src/styles/globals.css`. Tailwind utilities read
them: `bg-primary`, `text-muted-foreground`, `border-danger-border`.

**Dark is the default.** An app that sets no class on `<html>` renders dark. Add
`class="light"` to opt out. `class="dark"` also works, so `next-themes` with
`attribute="class"` behaves normally in both directions.

## Accent

One brand colour, a blue-purple, drives every interactive surface: primary
buttons, links, focus rings and the sidebar's active state.

<div className="not-prose flex gap-3 py-2">
  <div style={{ background: "#5b5bd6", color: "#fff", padding: "14px 18px", borderRadius: 6, fontSize: 13 }}>
    <strong>#5b5bd6</strong> — fill, both themes
  </div>
  <div style={{ background: "#4f46e5", color: "#fff", padding: "14px 18px", borderRadius: 6, fontSize: 13 }}>
    <strong>#4f46e5</strong> — link, light
  </div>
  <div style={{ background: "#a5a6ff", color: "#0d1117", padding: "14px 18px", borderRadius: 6, fontSize: 13 }}>
    <strong>#a5a6ff</strong> — link, dark
  </div>
</div>

Links use `text-link`, never `text-primary`: the fill is tuned for white text on
top of it, the link colour for reading against the page. A link inside a
sentence also needs `underline underline-offset-4` — colour alone fails
WCAG 1.4.1.

## Status

Four states, each with four jobs. Every pairing below clears 4.5:1 in both
themes; the numbers were measured, not guessed.

| Token | Job |
|---|---|
| `--x` | the fill on a button or badge (`bg-danger`) |
| `--x-foreground` | text on that fill (`text-danger-foreground`) |
| `--x-fg` | text or an icon on a page background (`text-danger-fg`) |
| `--x-subtle` / `--x-border` | the banner ground and its border |

    ["info", "#0969da", "#0969da", "#ddf4ff", "#1f6feb", "#79c0ff", "#0f1d2e"],

    ["danger", "#cf222e", "#cf222e", "#ffebe9", "#da3633", "#ff7b72", "#2a1517"],
  ].map(([name, ls, lfg, lsub, ds, dfg, dsub]) => (
    <div key={name} style={{ display: "flex", alignItems: "center", gap: 10 }}>
      <code style={{ minWidth: 76 }}>{name}</code>
      <span style={{ background: ls, width: 26, height: 22, borderRadius: 4 }} />
      <span style={{ background: lsub, color: lfg, padding: "3px 8px", borderRadius: 4, fontSize: 12 }}>light</span>
      <span style={{ background: ds, width: 26, height: 22, borderRadius: 4 }} />
      <span style={{ background: dsub, color: dfg, padding: "3px 8px", borderRadius: 4, fontSize: 12 }}>dark</span>
    </div>
  ))}
</div>

Two things worth knowing:

- **`--warning-foreground` is dark, not white.** White on any usable amber tops
  out around 3:1. Every other status fill takes white.
- **Never use the fill as text.** `text-danger` is `#da3633`, which is 3.8:1 on
  a dark card — it fails. That is what `--danger-fg` exists for.

`--destructive` is kept as an alias of `--danger` so upstream shadcn snippets
keep working. New code should say `danger`.

## Surfaces

| Token | Dark | Light | Use |
|---|---|---|---|
| `background` | `#0d1117` | `#ffffff` | the page |
| `card` / `popover` | `#151b23` | `#ffffff` | boxes, menus, dialogs |
| `foreground` | `#f0f6fc` | `#1f2328` | body text |
| `muted-foreground` | `#9198a1` | `#59636e` | secondary text |
| `secondary` | `#212830` | `#f6f8fa` | neutral button fill |
| `accent` | `#23233a` | `#f0f0fb` | hover surfaces, tinted toward the brand |
| `border` / `input` | `#3d444d` | `#d1d9e0` | all borders |
| `field` | `#0d1117` | `#ffffff` | input backgrounds |
| `tooltip` | `#3d444d` | `#24292f` | tooltip surface |

Note that shadcn's `--accent` is the *hover surface*, not the brand colour. The
brand accent is `--primary`.

## Radius

Flat: 6px on controls and boxes (`rounded-md`, `rounded-lg`), 4px small, 8px for
the largest surfaces.

## Typography

System stack (`-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans",
Helvetica, Arial`), mono is `ui-monospace, SFMono-Regular, "SF Mono", Menlo,
Consolas`. Page titles `text-2xl font-semibold tracking-tight`, body `text-sm`,
helper text `text-sm text-muted-foreground`.

## Spacing rules of thumb

- Page content padding: `p-6`
- Gap between page sections: `gap-6`
- Gap between form fields: `gap-5`
- Gap between inline controls: `gap-2`

## Overriding per app

Redefine any variable after importing the stylesheet:

```css
@import "@ziku/ui/styles.css";
:root { --primary: #0969da; --ring: #0969da; --link: #79c0ff; }
```
